# Argus — UI/UX аудит (по методологии ui-ux-designer)

Проведён на реальных скриншотах всех 5 разделов (Ассистент, Юниты, Лиды, Справки, Аналитика) + реальном коде (`globals.css`, `theme.tsx`). Не абстрактная критика — каждый пункт привязан к конкретному скриншоту или строке кода.

---

## 🎯 Вердикт

Тёмная тема выбрана осознанно — не белый SaaS-шаблон, не фиолетовый градиент. Шрифты (Onest + Golos Text) не входят в generic-блоклист (Inter/Roboto/Montserrat). Но **структура экранов — это классическая CRM**: карточки-сетка, дропдауны, таблицы с кнопкой "скачать". Единственный намёк на "не CRM" — раздел Ассистент, но именно он сейчас самый пустой из всех пяти (одно приветствие + 4 подсказки на весь экран). Это ровно то, что ты и предчувствовал: сейчас Argus выглядит как "CRM с вкладкой AI", а не как отдельная платформа.

## 🔍 Критические проблемы

### 1. В Справках колонка "Юнит" показывает необработанный UUID
**Проблема**: таблица справок показывает `639bf11c`, `a0f67173` вместо номера квартиры/здания.
**Почему это важно**: Recognition over Recall (Jakob's Law) — босс должен помнить/расшифровывать фрагмент UUID, чтобы понять, о какой квартире речь. Это буквально нечитаемо.
**Источник**: usability heuristic "recognition over recall", NN Group.
**Fix**: показывать `unit_number` + здание напрямую в этой колонке (join уже есть в БД, просто не выведен на фронт).
**Приоритет**: Critical, Effort: Low.

### 2. Справку можно только скачать — нет предпросмотра в дашборде
**Проблема**: единственное действие в списке справок — "Скачать". Это именно то, что ты просил исправить (#3).
**Почему это важно**: AI-генерируемый контент нельзя показывать как "готовый файл для скачивания" без возможности проверить его перед тем как открывать — это увеличивает трение и снижает доверие к тому, что реально сгенерировано.
**Fix**: инлайн-предпросмотр прямо в карточке справки (номер юнита, площадь, цена/м², план оплаты, ежемесячный платёж) рядом с кнопками Одобрить/Отклонить — не нужно скачивать файл, чтобы проверить цифры.
**Приоритет**: Critical, Effort: Medium.

### 3. Ассистент — почти пустой экран
**Проблема**: одно приветственное сообщение + 4 подсказки, дальше — чёрный экран до самого низа.
**Почему это важно**: это единственный раздел, который реально должен ощущаться как "мозг", а не как CRM-вкладка — а он сейчас самый неразвитый из пяти.
**Fix**: добавить постоянную ленту "что произошло, пока вас не было" (одобренные/отклонённые справки, новые лиды, изменения цен) — заполнить пространство информацией, а не пустотой.
**Приоритет**: High, Effort: Medium.

### 4. Юниты — сетка карточек без фильтра по цене/статусу/типу
**Проблема**: 153 юнита одним нескончаемым скроллом, фильтр только по зданию.
**Почему это важно**: Hick's Law — время принятия решения растёт логарифмически с числом вариантов без группировки.
**Fix**: фильтры по статусу (В продаже/Продано/Резерв/Бронь), типу комнат, сортировка по цене.
**Приоритет**: High, Effort: Low-Medium.

### 5. Таблица "Реальные цены по планам оплаты" — сплошные прочерки
**Проблема**: в Аналитике таблица цен по планам показывает "—" для всех зданий и планов, кроме тех что мы явно вводили руками.
**Почему это важно**: это не столько UX, сколько **возможный реальный баг** — босс открывает Аналитику и видит пустую таблицу там, где ожидает реальные цифры. Нужно проверить `payment_plan_rates` в БД отдельно от дизайна.
**Приоритет**: Critical (проверить), Effort: Low.

## 🎨 Эстетическая оценка

**Типографика**: Onest + Golos Text — приличный выбор, не generic, но довольно "безопасная modern SaaS" пара. Если хочешь, чтобы Ассистент ощущался визуально ИНАЧЕ, чем Юниты/Справки — дай именно этому разделу отдельный, более выразительный шрифт (editorial serif или экстремальный вес), чтобы визуально отделить "мозг" от "таблиц данных".

**Цвет**: 3 темы (gold/mono/teal) на почти чёрном фоне — хорошо, не клише. Но один и тот же акцентный цвет используется и для кнопки-действия ("Сгенерировать справку"), и для статус-тега ("В продаже"), и для активного пункта меню — нет вторичного цвета для иерархии. Упущенная возможность выделиться.

**Layout**: каждый раздел — это одна вертикальная колонка полноширинных панелей. Нет асимметрии, нет визуальной разницы между "AI-разделами" и "таблицами данных". **Это главная причина, почему сейчас всё читается как одна CRM**, а не как платформа с несколькими разными режимами работы.

## ✅ Что уже работает

- Тёмная связная цветовая система в 3 реальных вариантах — не ленивая инверсия
- Реальный выбор шрифтов, не дефолтный Inter/Roboto
- Навигация слева (совпадает с left-side-bias — NN Group 2024: пользователи проводят на 69% больше времени, глядя на левую половину экрана)
- Подсказки-чипы в Ассистенте снижают "страх пустого поля" (paper-blank-page friction) — правильный паттерн для AI-интерфейсов

## 🚀 Приоритет реализации (с учётом твоих 4 пунктов)

### Critical (сделать первым)
1. Юнит показывает UUID, не номер — **Effort: Low**
2. Проверить, реальный ли баг с пустой таблицей цен в Аналитике — **Effort: Low**
3. Инлайн-предпросмотр справки в дашборде вместо только "Скачать" (**твой пункт #3**) — **Effort: Medium**

### High (сделать скоро)
4. Функциональная глубина Ассистента — не просто чат + 4 чипа (**твой пункт #1**)
5. Генератор справок: либо более богатая форма ввода, либо ассистент-ведёт-диалог (**твой пункт #2**) — это решение дизайна, не просто задача на разработку. Я рекомендую **чат-подход** (ассистент делает, человек пишет текстом) вместо форм с полями — это лучше соответствует позиционированию "не CRM" и совпадает с исследованием: растущее текстовое поле для многошаговых задач работает лучше жёсткой формы.
6. Фильтры/сортировка в Юнитах

### Medium (приятно иметь)
7. Отдельный визуальный язык для Ассистента vs таблиц данных (шрифт/layout-асимметрия)
8. Второй акцентный цвет для настоящей иерархии (CTA vs статус vs навигация)

Если есть время только на одну вещь — **переосмысли Ассистента как настоящий мозг платформы, а не чат-виджет сбоку**.
